## Goal

Let the flash toast show the result of an Undo, so a later part of GH-869 can tell the seller, at once and in one short message, whether the sale they just saved was removed, was already gone, or could not be undone because there was no connection or something failed. This is front end only (`web/`) and builds on the flash toast from #982.

## Acceptance criteria

- `FlashMessage` accepts `{kind: 'undoResult', result: 'deleted' | 'gone' | 'offline' | 'failed'}`, and each result is rendered inside `.aviso-flotante`.
- `deleted` shows `AvisoExito` with "Sale deleted · the grams go back to stock" (`common:saleDeletedGramsBack`).
- `gone` shows `<Notice kind='notice' refusal={GONE_NOTICE}/>`, which reads "That is gone. The list is up to date."
- `offline` shows `<SinConexion/>`, and `failed` shows `<ErrorGenerico/>`.
- `gone`, `offline` and `failed` never show the success text.
- Each of the four results is on screen when shown and gone at 2.5 s (`DEFAULT_TOAST_MS`), checked with Testing Library and a fake clock.
- Any new toast shown while an Undo result is up replaces it, and only one toast is visible at a time.
- `saleDeletedGramsBack` is in the AvisoExito `SuccessToast` union and in `SUCCESS_TOASTS` in `web/src/architecture/e2eToastRule.test.ts`.
- The key is present in `common.ts`, `locales/en/common.json`, `baselineKeys/common.json` and `en.baseline.json`, added only where it was missing. If any copy file changed, en-XA is regenerated with `web/scripts/i18n/pseudo.ts`, never edited by hand.
- `TOAST_ELEMENTS` keeps its three entries, no `WalkState` is added, and no new copy text is added.

## Out of scope

- Wiring Undo to this rendering, and any retry after a failed Undo (a later part of GH-869).
- New copy, or a failure text specific to Undo.
- A longer duration for the failure or offline results.
- Rewording "grams" in the success text (the #330 sweep and the units part of GH-318).
- Changing the `@deprecated` comment on `saleDeletedGramsBack`.
- Any language other than English.

## Decisions

- Reuse `GONE_NOTICE`, `SinConexion` and `ErrorGenerico` for `gone`, `offline` and `failed`, with no Undo-specific text.
  - Reason: these elements already mean the same thing everywhere in the app, so the seller recognises them, and new text would add scope without a clear gain.
- Keep "Sale deleted · the grams go back to stock" as the success text.
  - Reason: it states the effect the seller cares about, the sale gone and the stock back, and it is an existing text, so the grams assumption stays with the #330 sweep.
- All four results last 2.5 s.
  - Reason: this matches every other toast; a longer failure toast would be a separate product decision.
- Add the copy key only where it is missing, and leave en-XA untouched if no copy file changes.
  - Reason: the key already exists in the four copy files, and en-XA is only ever generated by its script.
